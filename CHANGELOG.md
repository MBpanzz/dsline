# Changelog

## 0.0.1

Initial test version for repository publication.
- Fixes the remaining Windows flake, which was a *test* race against a platform rule, not a library bug: a named paging-file section (and its data) exists only while at least one handle is open, so a producer that sends and closes before a consumer has opened the channel destroys its own messages — the consumer then creates a fresh, empty region under the same name (same path, no data), which is exactly the `16 != 24` / `[]` shape CI kept reporting. The sharded cross-process tests now synchronise through a `multiprocessing.Barrier`: every worker opens its regions first, and only then may a producer send. The rule is documented in `docs/README.md`.
- Treats a misdetected section creator as an opener: `create_or_open` now takes the *recovery* path whenever the region's magic is already published, even if the OS claimed it created the section (`created && load_magic() == 0` is the only path to initialization). The previous guard avoided wiping a live ring but still left the duplicate creator with head/tail/sequence state at zero; recovering it is what an opener would do.
- Adds a `.cargo/config.toml` default (`PYO3_PYTHON`, `force = false`) so a bare `cargo build` / `cargo test` works on this machine: an abi3 extension links `python3.lib` on Windows, which only a CPython installation ships, and the MSYS2 python that PATH resolves has none (LNK1181). An explicitly set `PYO3_PYTHON` — the lane scripts, CI's interpreter — still wins.
- Shortens `wait_initialized`'s wall-clock bound to 5 s (the init pass is one header write per slot; the test that asserts the "region is not initialized" error waited the full 30 s before).
- Fixes a Windows data-loss bug that explains the intermittent CI failure in the sharded tests (a consumer reading an empty region whose path and depth matched the producer's). The paging-file section backend decided "I am the creator" from `GetLastError()` without clearing it first — and that reports the *thread's* last error, so a stale code from an earlier `CreateFileMappingW` on the same thread could make an **existing** section look newly created. The "creator" then ran the initialization pass, rewriting every slot header to FREE while leaving the cursors claiming messages were pending: any consumer of that region reads nothing, forever. One thread creating several shards (exactly what `ShardedChannel` does) makes it reachable. `SetLastError(0)` now precedes the call, and `initialize_region` refuses to re-initialize a region whose magic is already published — the duplicate creator opens it instead, so the guard holds even if the flag is wrong again. Regression test: `re_initializing_a_live_region_does_not_wipe_it`.
- Makes the sharded cross-process tests report *what they read and where*: each consumer now returns its shard index, the messages it saw, its shard's region path and queue depth, and each producer returns the paths of the shards it wrote to; both tests assert that the consumers' region paths equal the producers'. The Windows-only broadcast failure (`one consumer saw [] after 120 s`) is not reproducible locally — 0 failures in 30 runs under six CPU hogs — so the next occurrence has to carry its own evidence: the assertion message now contains both the paths and the depths.
- Fixes the Windows CI failure properly (both jobs, `test_broadcast_consumer_per_shard_sees_everything`): the worker's drain deadline must be *shorter* than the parent's wait, and the parent's wait must be long enough for the producer process to start at all. The first failure showed a worker reporting `[]` (its 20 s window had expired before the producer's first message), and the next showed only `_queue.Empty` (the parent's 60 s gave up before the worker's 120 s). Workers now drain for 120 s and parents wait 180 s, so a failure reports the worker's own view; every cross-process wait in the Python tests is 180 s (they return immediately when the flow is healthy, and one was as low as 5 s).
- Makes two more waits wall-clock (`wait_initialized`, `wait_for_full_size`), the same class of bug as the MPSC ones: a fixed 2048-yield budget measures the scheduler, so an opener racing a creator that is descheduled — several processes creating the same shards at once on a 2-core runner — gave up with "region is not initialized" while nothing was wrong.
- Gates the last probe-dependent test (`process_identity_of_a_live_self_is_alive`) and relaxes the cross-process drain deadlines: the sharded consumer's 20 s budget was observed expiring *before the producer's first message* on a Windows runner (`AssertionError: Lists differ: [] != [b'bc-0', ...]`), and `test_zero_copy.py` had a 10 s spin deadline. Both are 120 s now, with the reason recorded at the helper.
- Records a new open correctness item found while re-running both lanes in parallel on one machine: the two-producer MPSC test failed once with `send b: Channel(InvalidConfig("ring cursors are inconsistent"))` — the shared cursors diverged by more than the ring capacity, which the send guard should make impossible (`refresh_cursors`, lib.rs:3833). It did not reproduce in isolated runs (single lane, 40+ suites), so it is a rare race under heavy contention, and it is a plausible mechanism behind the once-observed hang. Not fixed; the guard's error is the only signal it leaves, and CI now names the failing test via annotations.
- Fixes the macOS build break the previous gating introduced: `spawn_dead_identity` was gated along with the reclaim tests, but the refusal-side test (`mpsc_reclaim_refuses_an_extent_crossing_a_committed_slot`) still calls it, so the crate did not compile on any platform without a probe (E0425). The helper is platform-neutral — spawning and reaping a child works everywhere; only *classifying* the identity needs a probe — so it is no longer gated. Reproduced locally with `cargo check --target x86_64-apple-darwin -p dsline-shm --all-targets`, which exercises the same cfg branches as macOS without needing its SDK.
- Relaxes the cross-process waits in the Python tests (15 s → 60 s in `test_sharded_channel.py` and `test_zero_copy.py`). The Windows 3.11 job failed on `test_broadcast_consumer_per_shard_sees_everything` because a runner has 2–4 cores and a cold page cache while the test starts four processes that each pay a fresh interpreter start plus the extension import.
- Makes the CI annotations survive cargo's colourised output (strip ANSI escapes before matching — the anchored patterns were failing on escape sequences) and prioritises what is emitted, since GitHub keeps at most 10 annotations per step: the failing test names first, then the exception and error lines.
- Extends the same platform gating to the crash-recovery tests, which is what the macOS jobs were still failing on: every test that asserts a reclaim *fired* needs a platform probe, so the five in `dsline-shm` and the three in `tests/python/test_shm_channel.py` are now gated to Windows/Linux while the refusal-side tests (a live writer's zombie, an identityless header, an extent crossing a committed slot) keep running everywhere — they hold for `Unknown` too. Counts are unchanged on both lanes (Rust 149/140, Python 137); macOS skips the gated ones.
- Fixes the CI diagnostic steps themselves: `shell: bash` runs the script with `-e`, so a failing `cargo test | tee` aborted the step before the annotation block could run (the first attempt reported only "exit code 101" with no annotations). Both test steps now clear errexit before the diagnostic block.

- Fixes what the first CI run on the pushed code found (the workflow had not run since 2026-06-06, so CI was seeing the whole September–October body of work for the first time). Ubuntu 3.12 and both Windows jobs passed; macOS failed, and the cause was deterministic: the writer-identity tests in `process.rs` assert what a *real* platform probe answers, but only Windows and Linux implement one (`imp::process_start_time`) while other platforms deliberately answer `Unknown` — those five tests are now gated to the platforms with a probe, and a new test pins the conservative default (`Unknown`, never reclaim) for the ones without, so macOS CI now checks the behaviour that platform actually has.
- Relaxes the timeouts the MPSC stress tests and the drop/reserve waits use (test config 10 s → 60 s, internal release/drop bounds 5 s → 30 s, the test's diagnostic deadline 60 s → 120 s). A CI runner has 2–4 cores for the whole suite in parallel, and a tight budget there measures the runner's scheduler rather than the channel; the Ubuntu 3.11 job failed the same way and does not reproduce locally under `taskset` at 2 or 4 cores (0 failures in 40 runs), so the budget is the part that has to be generous — the paths stay bounded, and a bounded failure is still better than the hang they replaced.
- Makes CI failures diagnosable from outside the repository: the Rust and Python test steps now tee their output and emit the failing test names (and `error[...]` lines) as `::error::` annotations. Without it a red run reports only "exit code 101", because the raw job log needs repository credentials.

- Fixes two MPSC bugs found by chasing the once-observed test hang, both of the same shape — a bound expressed in something other than wall-clock time, on a path that must not fail:
  - **`DropOldest` sends could fail.** `drop_oldest_message_mpsc` refused as soon as the cursors stood still over the COMMITTED grace period, but a *live* producer's in-flight reservation leaves the cursors standing still too — so a healthy `send` failed with `BufferFullError` whenever it raced another producer's write (reproduced 2/20 on Windows; the test asserting the documented "drop strategies keep `send` a successful call" was the only thing that noticed). The drop now distinguishes the two cases with the existing identity probe: a provably dead writer's leftover is reclaimed, a live one is waited out, and only a writer that neither commits nor dies within a 5 s bound fails the drop.
  - **A blocking send could wait past its timeout without bound.** `Backpressure::Block` applied the timeout per wait attempt inside the reservation loop, and each attempt returns `Ok` as soon as space appears — so a producer that kept losing the head CAS to a peer retried forever, never returning. This is the most plausible mechanism behind the hang observed once in the two-producer test (a stuck producer never signals completion, so the consumer's drain loop never ends — matching the captured state: a futex wait, two threads, the test's region file held). `reserve_slots` now takes a single deadline for the whole attempt.
  - Both bounds that gate these paths are now wall-clock rather than yield counts: a fixed yield budget is scheduler-dependent and fires on *healthy* peers under CPU oversubscription (the test harness runs the suite in parallel), which is how both bugs hid.
- Verification of the fixes: the Windows `dsline-shm` suite went from 2 failures in 20 runs to **0 in 25**; the drop fix and the reservation deadline are both exercised by the existing MPSC tests. The two-producer thread test also fails with a diagnostic now (producers done, ring depth, messages received) instead of hanging, and its producers signal completion through a `Drop` guard so a panicking producer cannot leave the consumer waiting forever.

- Replaces the frame checksum with CRC-32 (IEEE) — ADR-006. The previous byte-at-a-time FNV-1a is a serial dependency chain (`h = (h ^ byte) * prime`) that cannot be vectorised, and it dominated the copy path: measured in a release build it was 4.19 µs for a 4 KiB payload, ~63% of both the 8.29 µs send and the 4.47 µs receive. The implementation is `crc32fast` (folding multiply where the CPU supports it), the first dependency added to `dsline-core`. Because stored checksums change, this is a protocol change: `FRAME_VERSION` 1 → 2 and `REGION_FORMAT` 3 → 4, with regions from older builds rejected at open. The Python name → region-path mirror in `_shm.py` switches to `zlib.crc32` with it, while the sharded fan-out's *routing* hash stays FNV-1a (a documented, solver-checked contract, now its own `_fnv1a32` helper) so shard assignment does not move with the checksum.
- Fixes how performance is measured, which mattered more than any code change: `maturin develop` defaults to a **debug** build (wheels are release), and in debug a single 4 KiB checksum costs ~16 µs — more than an entire send. Every benchmark number published before this was measured against a debug extension. Both lanes gain release support (`DSLINE_RELEASE=1` for the python lane, plus a `bench` subcommand that always builds release first), and `docs/development.md` makes release the rule for performance numbers.
- Measured effect of the two corrections above on `dsline_shm` cross-process: 64 B 211.7k → **869.2k msg/s**, 1 KiB 109.1k → **626.0k**, 4 KiB 39.2k → **540.0k**, 64 KiB 3.5k → **130.9k** (7.99 GiB/s), latency p50 at 64 B 5.87 → **1.33 µs**. dsline is now first on latency at every size measured and ahead of `mp.Queue`, `mp.Pipe` and ZeroMQ on throughput; only the raw hand-rolled stdlib ring (no framing, no checksum, no state machine) is still ahead.
- Fixes a liveness hole in the MPSC reservation loop: `Backpressure::Block` applied its timeout per wait attempt, so a producer that kept losing the head CAS could wait past the configured timeout indefinitely (each individual wait returned `Ok`). The reservation now takes a single deadline for the whole attempt (`wait_for_space_until`), so a blocking send honours its timeout as a total bound. This is the most plausible mechanism behind a hang observed once in the MPSC thread test.
- Hardens that test so a future hang is a failure instead of a stuck binary: producers signal completion through a `Drop` guard (a panicking producer can no longer leave the consumer waiting for a signal that never comes) and the consumer's drain loop carries a 60 s deadline with a diagnostic (producers done, ring depth, messages received).
- Adds a `timing_probe` (ignored) test to `dsline-shm` that measures the copy path's per-operation costs in isolation — checksum, frame encode, region write and read, and the full channel send/`try_recv` at 64 B and 4 KiB — so the ratios cited in `docs/benchmarks.md` can be reproduced: `cargo test --release -p dsline-shm --lib timing_probe -- --ignored --nocapture`.
- Also fixes `python/dsline/_shm.py`, which had its own copy of the checksum and would otherwise have computed region paths the channel does not use, and adds `matches the region the channel actually opens` coverage to the CLI test that caught it.

- Adds `try_recv()` — the non-blocking, non-raising receive — to the Rust channel (`PersistentShmChannel::try_recv`) and to both Python classes (`ShmChannel`, `FileChannel`). It returns `None` when nothing is readable right now (an empty ring, or a producer mid-batch whose head cursor is not published) with a single slot-header read: no COMMITTED grace poll and no exception. `recv()` costs a 256-iteration grace poll and raises `BufferEmptyError` on every empty attempt, so an exception-driven poll loop measures the interpreter's exception path rather than the channel — the benchmark's dsline consumers now poll with `try_recv()`. Crash recovery is preserved (a dead writer's leftover at the tail is reclaimed on the spot, then the read is retried), and it advances the same sequence state as `recv()`, so the two can be mixed.
- Releases the GIL around blocking sends (`py.allow_threads` in both channel classes). A `Block` send spins in Rust until the consumer frees space; while it held the GIL, a consumer running as another thread of the same process could never drain the ring, so the send blocked until its timeout and failed — an in-process deadlock in the documented threaded pattern. With a handle per thread the pattern now runs at full speed (200/200 messages instantly, against 4/200 + `BufferFullError` before). A handle is still serialized by an internal lock, so two threads must not share one; that contract is now documented in `README.md` and `docs/README.md`.
- Fixes the Windows lane's silent stale-extension trap: `maturin develop` needs `CONDA_PREFIX` (or `VIRTUAL_ENV`) and otherwise fails with "Couldn't find a virtualenv or conda environment" — a failure that a piped log hides, after which the Python tests keep running against the previously built extension. The Windows lane had been testing a `.pyd` built on 2026-10-02 ever since. Adds `scripts/windows-test.sh` (the Windows lane as one entry point, pinning `PYO3_PYTHON` and `CONDA_PREFIX` and printing the built extension's timestamp), and documents the trap in `docs/development.md`.
- Adds the first Linux (tier-1) benchmark numbers to `docs/benchmarks.md`: dsline now has the **best latency of every backend measured** (5.87 µs one-way p50 at 64 B, against 15.1 µs for `mp.Pipe`, 29.2 µs for the hand-rolled stdlib ring, 130 µs for dsline itself on Windows). Throughput is still 5–20× behind from 1 KiB up; the report localises the remaining cost in the copy path's frame encode/decode plus two FNV-1a checksum passes per message (~25 µs at 4 KiB vs ~1.1 µs for the stdlib ring), which is a design change rather than a tuning knob. The in-process section — which previously hung forever — now measures 93.3k msg/s at 64 B and is documented as GIL-bound (dsline is a transport, not an in-process queue).
- Adds `try_recv` tests (a Rust unit test covering empty/polled/drained/closed plus sequence continuity with `recv`, and four Python cases) and a Python threading regression test that fails without the GIL release. Python tests 132 → 137; Rust unit tests 80 → 81 in `dsline-shm` (148 on Windows, 139 on Linux).
- Adds timeouts to the benchmark's in-process section (`_inproc_wall`) so a dead worker thread fails loudly instead of hanging the harness forever, and drops a stale comment claiming the in-process number is dominated by an O(capacity) refresh scan.
- Fixes the benchmark's `shm_stdlib` baseline, which made runs abort intermittently: its consumer opened the shared-memory block while the creator was still sizing it (`ValueError: cannot mmap an empty file` — the same zero-length window dsline's own file backends now wait out) and the retry loop only caught `FileNotFoundError`; and neither worker unlinked the block it created, so `/dev/shm` blocks and resource-tracker warnings accumulated across runs.

- Adds the mandatory Linux verification lane on WSL Ubuntu (`scripts/wsl-test.sh`, `docs/development.md`, `AGENTS.md`): every change is now verified on Windows and on Linux, because Linux is the tier-1 platform, its `MAP_SHARED` needs no `FlushViewOfFile` (so the transport's real performance numbers only exist there), and the platform branches (`/proc` liveness probe, storage-backend choice, region directory) are exercised only there. The lane is idempotent (`setup` / `rust` / `python` / `verify` / `bench` / `all`), installs rustup + a `--system-site-packages` venv + maturin, and keeps the cargo target directory on the Linux filesystem (the sources stay on `/mnt/c` so the lane tests the working tree). Mirror overrides are built in: the official Rust CDN measured ~31 KB/s on this machine against ~9.8 MB/s from a mirror.
- Fixes the Linux defects that lane immediately surfaced. The code had been developed on Windows only, and CI had not run on the last seven commits (local `main` was seven ahead of `origin/main`):
  - `dsline-shm` did not compile on Linux at all: `current_process_start_time()` applied `unwrap_or` to a `Result<Option<u64>, ()>` and returned the inner `Option`, so the whole `/proc`-based crash-recovery path was unbuildable (2 × E0308).
  - `dsline-python` did not compile on Linux: `PySlice::indices` takes `c_long`, which is 32-bit on Windows and 64-bit on Linux, so `slice.indices(size as i32)` was Windows-only (2 × E0308); the cast is now `as std::os::raw::c_long` in both the `ShmWriteBuffer` slice-assignment and the `ShmReadView` `__getitem__` paths.
  - File-backed `create_or_open` could spuriously fail on Unix: the creator publishes the path with `create_new` before its `set_len` runs, so a peer opening in that window saw a short file and got `InvalidConfig("file storage is smaller than expected")`. Both file backends now wait that window out with the same bounded spin `wait_initialized` uses (new `wait_for_full_size`), so concurrent first-open of one named channel works; a genuinely mismatched capacity still reports the short length after the spin. Reproduced by `test_sharded_channel.ShardedCrossProcessTests.test_two_producers_three_consumers_exactly_once` (2 producers × 3 consumers opening the same shards), which now serves as the regression test.
- Adds `docs/development.md` (environment matrix, exact commands per lane, pass criteria, and the known traps: `PYO3_PYTHON` for the Windows lane, `MSYS_NO_PATHCONV=1` plus script files instead of `wsl.exe ... bash -c` for the WSL lane, a venv instead of `pip install --break-system-packages`), plus a repository-level `AGENTS.md` that makes the two-lane rule binding for future sessions.
- Verified on both lanes after the fixes: Windows 147 unit + 5 doc tests, Linux 138 unit + 5 doc tests (the 9-test difference is `#[cfg(windows)]` section-backend tests), 132 Python tests and 84 solver checks on each platform.

- Adds the zero-copy alloc/publish path (roadmap §4.2), the last open 0.1.0 feature: `alloc(size)` reserves one slot and returns a writable lease whose writes land directly in the shared region (the payload is born in shared memory — no intermediate frame buffer, no transport copy); `publish(buf)` verifies the payload where it lies (checksum through the backend's zero-copy read window, no copy-out), writes the frame header, seals the buffer (further writes raise), and commits the slot; `recv_view()` returns a read-only view over the same bytes with partial reads (`view.read(off, n)` copies only the requested range) instead of an eager whole-message copy. The Python surface (`ShmWriteBuffer` / `ShmReadView`, shared by `ShmChannel` and `FileChannel`) supports `write()` / slice assignment / `read` / `read_all` / `__getitem__` / `release()` / with-blocks, and `stats()` gained `pinned_slots`.
- Adds the pin-floor protocol that makes held views safe (roadmap §4.4): a recv'd view transitions its slot COMMITTED → PINNED with the consumer's identity (the mirror of the writer-identity stamping), and a new `pin_floor` word in the region header records the smallest pinned cursor value. Every producer's send guard derives its occupancy from the floor (`head - floor` counts exactly the unusable slots: pinned plus released-but-behind-a-pin), so the ring can never wrap onto a slot a live view is reading. Updates are CAS-structured so a concurrent pinner's lower floor is never clobbered and a phantom floor self-heals at the next release or open; the worst case in every race window is a spurious `BufferFull`, never a silent overwrite (the Free-state check backs every physical write).
- Adds zero-copy crash recovery (roadmap §6, consumer side): a consumer that dies holding views leaves PINNED slots behind the tail; `reclaim_dead_pinned` applies the same decision table as dead writers (double-read stability, identity magic, platform liveness probe — `Alive`/`Unknown` pins are never touched) at open and in `reclaim_stale()`, and the open path rebuilds the pin floor from the ring afterwards. The recovery bias now excludes pins in the normal cursor regime (they are counted through the floor instead) so the guard does not double-book them.
- Grows the region header to 32 bytes (`[head: u64 @ 0] [tail: u64 @ 8] [magic: u32 @ 16] [format: u32 @ 20] [pin_floor: u64 @ 24]`, format version 3) and rejects regions written by older builds at open — delete stale region files when upgrading.
- Boundaries of the milestone: `alloc` is single-producer only (an unpublished MPSC reservation would head-of-line block the ring for as long as the buffer is held) and both `alloc` and `recv_view` reject `DropOldest` channels (a forced drop may free a pinned slot); zero-copy messages are single-slot (`size <= slot_size`, chunked messages stay on the copy path); Python reads are explicit copies of the requested range (buffer-protocol views / numpy interop need the pyo3 0.23 `__getbuffer__` API and are future work). The safety gate (roadmap §4.3) is covered by unit tests, the new solver checks, and the replay pass; Miri/loom-style model checking of the cross-process atomics remains out of reach for the FFI-backed state machine and is documented in ADR-005.

Adds 18 Python tests (114 → 132): the same surface through Python plus cross-process zero-copy delivery (spawn producer alloc/publish, parent recv_view) and a cross-process pin test where a spinning producer must not overwrite the pinned message.
- Extends `verify/check_invariants.py` to 84 checks (77 → 84): Z3 proves the pin-floor guard sound (Z6.1: `head+needed <= floor+cap` never touches a pinned slot), tight (Z6.2: one slot over collides), and degenerate to the classic SPSC guard under the no-pins sentinel (Z6.3); CP-SAT bounded-checks the wrap-boundary schedule — guarded claims never touch a pinned slot while the unguarded twin reaches one (C13/C13b); SCIP cross-checks the max single-slot zero-copy payload as a MIP optimum over the region-fit and capacity bounds (S10); a new R8 replay section exercises lease/seal/pin/rebuild/release through the real channel including the second-handle floor rebuild.
- Adds frame-header-level encode/decode to dsline-core (`encode_frame_header` / `decode_frame_header`) so the publish path writes only the 50-byte header over the in-place payload and the view path validates a frame without requiring the payload to be contiguous with it.
- Adds the sharded multi-consumer channel (roadmap §5.5 分片 MPMC): `dsline.ShardedChannel` composes N named Rust-backed channels into a fan-out with three routing strategies — `round_robin` (per-producer counter, N consecutive sends cover every shard exactly once), `hash` (`FNV-1a-32(key or payload) % shards`, stateless so every process routes the same key to the same shard and per-key ordering is preserved by the shard FIFO), and `broadcast` (every shard receives the full stream; a consumer bound to one shard sees everything). Consumers bind via `shard(i)` / `shards()`; `recv_any()` polls all shards round-robin and returns `(shard_index, payload)` or `None`; `shard_for()` exposes the routing function; `stats()` reports per-shard stats. One consumer per shard (the shards are ordinary SPSC/MPSC channels; every opener must agree on `multi_producer`).
- Adds 10 Python tests (99 → 114 with the crash-recovery cases): routing coverage, per-key FIFO, broadcast fan-out, `recv_any`, config validation, and cross-process exactly-once delivery (2 producer processes × 3 consumer processes through real named channels) plus a broadcast consumer-group test.
- Extends `verify/check_invariants.py` to 77 checks (62 → 77): Z3 proves the round-robin bijection (Z5.1), the FNV-1a step injectivity and fold composition behind the hash routing (Z5.2), and the shard range (Z5.3); CP-SAT bounded-checks the fan-out accounting invariant (C11: a shard's delivered count cannot differ from its assigned count while the total stays loss-less) and the broadcast amplification (C12); SCIP proves the round-robin balance optimality (S9: min-max load == ceil(P/N), max-min == floor(P/N) as MIP optima under the cycle constraint); a new R7 replay section runs the real cross-process fan-out (2 producers × 3 consumers exactly-once, broadcast consumer groups, hash determinism across handles).
- Adds crash recovery via writer identity (roadmap §6): every WRITING slot header now records the writer's `pid + start_time` (plus a per-handle epoch, a unix-ns timestamp, and the message's reserved slot count), published behind an identity magic that lands after a release fence — a reader that observes the magic never sees a torn identity. Before reclaiming a leftover slot, any handle verifies the recorded identity with a platform liveness probe (`OpenProcess` + `GetProcessTimes` on Windows, `/proc/<pid>/stat` field 22 on Linux, conservative `Unknown` elsewhere): a slot is reclaimed only when the writer is provably dead, never for an `Alive` or `Unknown` classification, and never for a header without the identity magic. SPSC mode reclaims at open and at the recv gate (beyond-cursor leftovers retire their `recovery_bias` credit); MPSC mode reclaims at the gate, freeing exactly the recorded reservation extent and CAS-advancing the shared tail past it — the live message behind a dead reservation becomes deliverable instead of wedging the ring.
- Adds `dsline.process_identity()`, `ShmChannel.reclaim_stale()` / `FileChannel.reclaim_stale()` (the roadmap's explicit owner cleanup), `reclaimed_slots` in `stats()`, and a test-only `_debug_leave_zombie` helper that simulates a killed writer deterministically.
- Fixes a latent cursor inversion found while building the recovery path: a consumer that read a COMMITTED slot whose head count was not yet published (a producer mid-batch, or a producer crashed between the slot commits and the head store) advanced the tail cursor past the head cursor, and the next refresh rejected the ring as inconsistent. The refresh now recognizes the orphan regime (tail ahead by up to capacity) and derives the depth from the recovery bias; the consumed orphan retires its bias credit instead of moving the cursors into an invalid state (CP-SAT C10 reproduces the pre-fix inversion and proves the regime rule covers every protocol-reachable state).
- Grows the persistent slot header to 48 bytes (identity fields + reservation extent + magic) and the region header to 24 bytes (a `format` word, currently 2): regions written by older builds are rejected at open instead of being misinterpreted — delete stale region files when upgrading.
- Adds cross-process crash-recovery tests (a spawned worker leaves a zombie and exits; the parent verifies reclaim at open, at the gate, the live-writer conservative default, and `reclaim_stale` idempotence); 9 new Rust unit tests (59 → 68) and 5 new Python test cases (99 → 104).
- Extends `verify/check_invariants.py` to 62 checks (43 → 62): Z3 proves the reclaim decision table sound (Z4.1: reclaim fires only on a provably dead identity; the identity magic + double-read never fabricates an identity (Z4.2); the resync rule adopts the post-crash sequence exactly once (Z4.3); the bias accounting stays collision-free after reclaims (Z4.4)); CP-SAT proves a dead reservation wedges the ring pre-fix and that the reclaim restores progress post-fix (C8), that a reclaim never crosses a live message (C9, reservation exclusivity), and reproduces/proves the orphan cursor regimes (C10); SCIP cross-checks the region-size formula with the identity header (S7) and the minimal tail advance == recorded extent (S8); a new R6 replay section exercises open-time reclaim, gate reclaim + resync, the live-writer default, and `reclaim_stale` through the real implementation.

- Implements fixed-slot SPSC bytes channel prototype over in-process storage.

- Adds memory and file-backed fixed-slot storage backends.
- Adds multi-slot chunking for bytes messages larger than one slot.
- Exposes Python `dsline.ShmChannel` through PyO3.
- Adds `DropNewest` and `DropOldest` backpressure strategies for fixed-slot SPSC channels.
- Aligns Python `FileChannel` stats, `recv_with_seq`, and backpressure options with `ShmChannel`.
- Aligns Python `FileChannel.send()` bytes-like input handling with `ShmChannel.send()`.
- Adds real cross-process shared-memory channels: `ShmChannel` is now a named mmap-backed channel (region files in the platform runtime directory), and `FileChannel` memory-maps its backing file instead of per-operation seek/flush syscalls.
- Adds shared head/tail cursors as the ring position source: the per-operation O(capacity) slot-header scan is replaced by an O(1) `refresh_cursors` over two shared monotonic slot counts in the region header, killing the refresh scan cost documented by the benchmarks. The full scan runs once per open (recovery): it rebuilds the producer's next message sequence, the consumer's expected sequence, and steps over in-flight WRITING slots left by a crashed writer; `recovery_bias` keeps those leftovers in the queue depth so the send guard never over-commits a physically full ring.
- Adds a COMMITTED gate with a bounded poll to the receive path: the head cursor is published together with the whole batch, so a crash-free run never exposes an uncommitted slot, and a WRITING slot that survives the grace period (a crash leftover) is surfaced as an empty ring instead of an infinite poll.
- Publishes batches with one flush per message on Windows (page-local flushes fall back for large offsets): the raw FlushViewOfFile cost (~45 µs per call on this machine) is measured and documented in `docs/benchmarks.md`.
- Replaces the file-backed mapping with a named paging-file section as the Windows storage backend for named channels (`SectionShmSlotStorage`): `CreateFileMappingW` on the system paging file (`multiprocessing.shared_memory` style), which is coherent across processes without `FlushViewOfFile` — the measured per-message flush cost disappears from the Windows send/recv path. The section name derives from the resolved region path (`Local\dsline-<digest>.bin`), no backing file is created on Windows, and the section dies with its last handle (no stale-region cleanup). `ShmChannel` selects the backend per platform: paging-file section on Windows, file-backed mapping elsewhere.
- Grows the region header to 20 bytes (`[head: u64 @ 0] [tail: u64 @ 8] [magic: u32 @ 16]`): the creator initializes every slot header and publishes `REGION_MAGIC` last (release store); openers poll for it before recovering the ring, so no peer observes a half-initialized region — required by the section backend, where a fresh region is zero-filled and indistinguishable from mid-init. `create_or_open` on named sections is atomic (the OS guarantees exactly one creator).
- Adds an opt-in multi-producer (MPSC) mode (`SpscConfig.multi_producer`, exposed as `multi_producer=True` on `ShmChannel` and `FileChannel`): producers claim disjoint slot ranges with a hardware CAS on the shared head cursor (the reservation is the linearization point, and the send guard runs on the reservation attempt, so two producers can never over-commit the ring), then write each slot through `WRITING` → `COMMITTED` as before. The consumer's per-slot COMMITTED gate absorbs the in-flight window, and the strict per-message sequence check is skipped in this mode (a single producer's sequence order is not the reservation order; ordering and integrity come from ring position, the commit gate, and the checksum). The mode is baked into the region magic (`DSL2` vs `DSL1`), so openers that disagree fail at open instead of misinterpreting the ring. `DropOldest` under concurrency advances the tail with a CAS over the dropped message's slot count (concurrent droppers never drop the same message twice) and force-releases the slot after the winning CAS (the consumer may have pinned it in between); the write side waits out the release window of a concurrent drop.
- Adds MPSC tests: two-thread producer stress (interleaved single-slot and chunked messages, every payload exactly once), concurrent `DropOldest` without double-drops, mode-mismatch rejection, crashed-writer leftovers under the reservation protocol, and a Windows section-backend round trip; 5 new Rust unit tests (48 → 53). Extends the solver verification with W1/W2 (Z3: the reservation guard implies every reserved count's slot is free; linearized CAS reservations are disjoint) and R5 (two-producer replay through the real implementation); 40 → 43 checks.
- Exposes `multi_producer` in Python channel `stats()` and adds a two-process multi-producer round trip to the Python test suite (85 tests).
- Composes the roadmap's declarative Pipeline API on top of the Rust pull engine: a `dsline.ops` module with deferred operator specs (`filter_expr`, `map_expr`, `filter_py`, `map_py`, `batch`, `select`, and the batch UDF variants) and a Python `Pipeline` wrapper adding `pipe(*ops)`, `sink(url)` (shm/file transports), and `run(source=None)` (drain the transport source, apply operators, send results to the sink). The existing imperative methods (`filter_expr`, `collect`, `send_to`, `receive_from`, ...) delegate unchanged, so all prior call sites keep working.
- Adds `dsline shm` region management to the CLI: `dir`, `list`, `inspect <name>`, `cleanup --older-than <90s|30m|2h|1d>`, and `remove <name>`, with `--json` on every subcommand. The name→file mapping mirrors `dsline-shm` (FNV-1a checksum32 of the name); on Windows named channels use sections and leave no files, so these commands report empty state there.
- Adds 14 Python tests for the new surface (declarative chaining, end-to-end `from_transport → pipe → sink → run` through real shared-memory channels, and CLI region management against a redirected runtime directory); 85 → 99 tests.
- Extends `verify/check_invariants.py` with cursor-protocol checks: Z3 proves the wrap guard partitions the circle and the send guard (incl. the crash-recovery bias) never writes into an occupied index; CP-SAT proves the cursor gate theorem (crash-free depth never includes an uncommitted slot) and witnesses the crash-leftover zombie state; SCIP verifies the cursor-depth and batch-flush bounds as MIP optima; the dual-handle replay (R4) runs a producer and a consumer over one region through the real implementation.
- Adds Rust unit tests for the cursor protocol: dual-handle round trips, crash-recovery zombie skipping, the biased send guard, WRITING-only ring reads, and rejoin-after-drain.
- Adds `SlotRegionIo` byte-range storage trait with file and memory-mapped backends, `MmapSlotStorage` (memmap2), and name-to-region resolution (`shm_region_path`).
- Generalizes `PersistentShmChannel` over the storage backend with a `create_or_open` constructor for named channels.
- Reports chunk metadata, chunk payload, and maximum message size in channel stats.
- Adds `dsline info` and `dsline bench shm` CLI entry points.
- Adds first cross-process tests (spawn-based producer/consumer round-trips for `ShmChannel` and `FileChannel`, including chunked messages).
- Adds solver-based invariant verification (`verify/check_invariants.py`) with Z3, CP-SAT, and SCIP: sequence-ordering properties, send-plan arithmetic, ring invariants, formal reproduction of the `len`-underflow bug, recovery inference, and replay against the implementation.
- Adds cross-process benchmark harness (`benches/cross_process.py`) vs mp.Queue/mp.Pipe/stdlib shared_memory/ZeroMQ/pynng with throughput, latency, and in-process sections; results in `docs/benchmarks.md`.
- Fixes cross-process races found by the stress tests: Windows file-backed mmap visibility now uses `flush_async_range` (FlushViewOfFile) instead of `flush_range` (FlushFileBuffers disk sync, ~1.2 ms/message); tail inference is now min-seq over committed/pinned slots (correct for gapped rings); a WRITING-only ring behaves as empty; chunked-receive error paths release the pinned slot.
