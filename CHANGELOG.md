# Changelog

## 0.0.1

Initial test version for repository publication.

- Adds the sharded multi-consumer channel (roadmap §5.5 分片 MPMC): `dsline.ShardedChannel` composes N named Rust-backed channels into a fan-out with three routing strategies — `round_robin` (per-producer counter, N consecutive sends cover every shard exactly once), `hash` (`FNV-1a-32(key or payload) % shards`, stateless so every process routes the same key to the same shard and per-key ordering is preserved by the shard FIFO), and `broadcast` (every shard receives the full stream; a consumer bound to one shard sees everything). Consumers bind via `shard(i)` / `shards()`; `recv_any()` polls all shards round-robin and returns `(shard_index, payload)` or `None`; `shard_for()` exposes the routing function; `stats()` reports per-shard stats. One consumer per shard (the shards are ordinary SPSC/MPSC channels; every opener must agree on `multi_producer`).
- Adds 10 Python tests (99 → 114 with the crash-recovery cases): routing coverage, per-key FIFO, broadcast fan-out, `recv_any`, config validation, and cross-process exactly-once delivery (2 producer processes × 3 consumer processes through real named channels) plus a broadcast consumer-group test.
- Extends `verify/check_invariants.py` to 77 checks (62 → 77): Z3 proves the round-robin bijection (Z5.1), the FNV-1a step injectivity and fold composition behind the hash routing (Z5.2), and the shard range (Z5.3); CP-SAT bounded-checks the fan-out accounting invariant (C11: a shard's delivered count cannot differ from its assigned count while the total stays loss-less) and the broadcast amplification (C12); SCIP proves the round-robin balance optimality (S9: min-max load == ceil(P/N), max-min == floor(P/N) as MIP optima under the cycle constraint); a new R7 replay section runs the real cross-process fan-out (2 producers × 3 consumers exactly-once, broadcast consumer groups, hash determinism across handles).
- Adds crash recovery via writer identity (roadmap §6): every WRITING slot header now records the writer's `pid + start_time` (plus a per-handle epoch, a unix-ns timestamp, and the message's reserved slot count), published behind an identity magic that lands after a release fence — a reader that observes the magic never sees a torn identity. Before reclaiming a leftover slot, any handle verifies the recorded identity with a platform liveness probe (`OpenProcess` + `GetProcessTimes` on Windows, `/proc/<pid>/stat` field 22 on Linux, conservative `Unknown` elsewhere): a slot is reclaimed only when the writer is provably dead, never for an `Alive` or `Unknown` classification, and never for a header without the identity magic. SPSC mode reclaims at open and at the recv gate (beyond-cursor leftovers retire their `recovery_bias` credit); MPSC mode reclaims at the gate, freeing exactly the recorded reservation extent and CAS-advancing the shared tail past it — the live message behind a dead reservation becomes deliverable instead of wedging the ring.
- Adds `dsline.process_identity()`, `ShmChannel.reclaim_stale()` / `FileChannel.reclaim_stale()` (the roadmap's explicit owner cleanup), `reclaimed_slots` in `stats()`, and a test-only `_debug_leave_zombie` helper that simulates a killed writer deterministically.
- Fixes a latent cursor inversion found while building the recovery path: a consumer that read a COMMITTED slot whose head count was not yet published (a producer mid-batch, or a producer crashed between the slot commits and the head store) advanced the tail cursor past the head cursor, and the next refresh rejected the ring as inconsistent. The refresh now recognizes the orphan regime (tail ahead by up to capacity) and derives the depth from the recovery bias; the consumed orphan retires its bias credit instead of moving the cursors into an invalid state (CP-SAT C10 reproduces the pre-fix inversion and proves the regime rule covers every protocol-reachable state).
- Grows the persistent slot header to 48 bytes (identity fields + reservation extent + magic) and the region header to 24 bytes (a `format` word, currently 2): regions written by older builds are rejected at open instead of being misinterpreted — delete stale region files when upgrading.
- Adds cross-process crash-recovery tests (a spawned worker leaves a zombie and exits; the parent verifies reclaim at open, at the gate, the live-writer conservative default, and `reclaim_stale` idempotence); 9 new Rust unit tests (59 → 68) and 5 new Python test cases (99 → 104).
- Extends `verify/check_invariants.py` to 62 checks (43 → 62): Z3 proves the reclaim decision table sound (Z4.1: reclaim fires only on a provably dead identity; the identity magic + double-read never fabricates an identity (Z4.2); the resync rule adopts the post-crash sequence exactly once (Z4.3); the bias accounting stays collision-free after reclaims (Z4.4)); CP-SAT proves a dead reservation wedges the ring pre-fix and that the reclaim restores progress post-fix (C8), that a reclaim never crosses a live message (C9, reservation exclusivity), and reproduces/proves the orphan cursor regimes (C10); SCIP cross-checks the region-size formula with the identity header (S7) and the minimal tail advance == recorded extent (S8); a new R6 replay section exercises open-time reclaim, gate reclaim + resync, the live-writer default, and `reclaim_stale` through the real implementation.
- Adds Rust workspace skeleton for core, shm, transport, pipeline, ops, and Python bindings.
- Implements fixed-slot SPSC bytes channel prototype over in-process storage.
- Adds frame header, chunk flags, and metadata TLV encode/decode.
- Adds memory and file-backed fixed-slot storage backends.
- Adds multi-slot chunking for bytes messages larger than one slot.
- Exposes Python `dsline.ShmChannel` through PyO3.
- Adds `DropNewest` and `DropOldest` backpressure strategies for fixed-slot SPSC channels.
- Aligns Python `FileChannel` stats, `recv_with_seq`, and backpressure options with `ShmChannel`.
- Aligns Python `FileChannel.send()` bytes-like input handling with `ShmChannel.send()`.
- Adds real cross-process shared-memory channels: `ShmChannel` is now a named mmap-backed channel (region files in the platform runtime directory), and `FileChannel` memory-maps its backing file instead of per-operation seek/flush syscalls.
- Adds shared head/tail cursors as the ring position source: the per-operation O(capacity) slot-header scan is replaced by an O(1) `refresh_cursors` over two shared monotonic slot counts in the region header, killing the refresh scan cost documented by the benchmarks. The full scan runs once per open (recovery): it rebuilds the producer's next message sequence, the consumer's expected sequence, and steps over in-flight WRITING slots left by a crashed writer; `recovery_bias` keeps those leftovers in the queue depth so the send guard never over-commits a physically full ring.
- Adds a COMMITTED gate with a bounded poll to the receive path: the head cursor is published together with the whole batch, so a crash-free run never exposes an uncommitted slot, and a WRITING slot that survives the grace period (a crash leftover) is surfaced as an empty ring instead of an infinite poll.
- Publishes batches with one flush per message on Windows (page-local flushes fall back for large offsets): the raw FlushViewOfFile cost (~45 µs per call on this machine) is measured and documented in `docs/benchmarks.md`.
- Replaces the file-backed mapping with a named paging-file section as the Windows storage backend for named channels (`SectionShmSlotStorage`): `CreateFileMappingW` on the system paging file (`multiprocessing.shared_memory` style), which is coherent across processes without `FlushViewOfFile` — the measured per-message flush cost disappears from the Windows send/recv path. The section name derives from the resolved region path (`Local\dsline-<digest>.bin`), no backing file is created on Windows, and the section dies with its last handle (no stale-region cleanup). `ShmChannel` selects the backend per platform: paging-file section on Windows, file-backed mapping elsewhere.
- Grows the region header to 20 bytes (`[head: u64 @ 0] [tail: u64 @ 8] [magic: u32 @ 16]`): the creator initializes every slot header and publishes `REGION_MAGIC` last (release store); openers poll for it before recovering the ring, so no peer observes a half-initialized region — required by the section backend, where a fresh region is zero-filled and indistinguishable from mid-init. `create_or_open` on named sections is atomic (the OS guarantees exactly one creator).
- Adds an opt-in multi-producer (MPSC) mode (`SpscConfig.multi_producer`, exposed as `multi_producer=True` on `ShmChannel` and `FileChannel`): producers claim disjoint slot ranges with a hardware CAS on the shared head cursor (the reservation is the linearization point, and the send guard runs on the reservation attempt, so two producers can never over-commit the ring), then write each slot through `WRITING` → `COMMITTED` as before. The consumer's per-slot COMMITTED gate absorbs the in-flight window, and the strict per-message sequence check is skipped in this mode (a single producer's sequence order is not the reservation order; ordering and integrity come from ring position, the commit gate, and the checksum). The mode is baked into the region magic (`DSL2` vs `DSL1`), so openers that disagree fail at open instead of misinterpreting the ring. `DropOldest` under concurrency advances the tail with a CAS over the dropped message's slot count (concurrent droppers never drop the same message twice) and force-releases the slot after the winning CAS (the consumer may have pinned it in between); the write side waits out the release window of a concurrent drop.
- Adds MPSC tests: two-thread producer stress (interleaved single-slot and chunked messages, every payload exactly once), concurrent `DropOldest` without double-drops, mode-mismatch rejection, crashed-writer leftovers under the reservation protocol, and a Windows section-backend round trip; 5 new Rust unit tests (48 → 53). Extends the solver verification with W1/W2 (Z3: the reservation guard implies every reserved count's slot is free; linearized CAS reservations are disjoint) and R5 (two-producer replay through the real implementation); 40 → 43 checks.
- Exposes `multi_producer` in Python channel `stats()` and adds a two-process multi-producer round trip to the Python test suite (85 tests).
- Composes the roadmap's declarative Pipeline API on top of the Rust pull engine: a `dsline.ops` module with deferred operator specs (`filter_expr`, `map_expr`, `filter_py`, `map_py`, `batch`, `select`, and the batch UDF variants) and a Python `Pipeline` wrapper adding `pipe(*ops)`, `sink(url)` (shm/file transports), and `run(source=None)` (drain the transport source, apply operators, send results to the sink). The existing imperative methods (`filter_expr`, `collect`, `send_to`, `receive_from`, ...) delegate unchanged, so all prior call sites keep working.
- Adds `dsline shm` region management to the CLI: `dir`, `list`, `inspect <name>`, `cleanup --older-than <90s|30m|2h|1d>`, and `remove <name>`, with `--json` on every subcommand. The name→file mapping mirrors `dsline-shm` (FNV-1a checksum32 of the name); on Windows named channels use sections and leave no files, so these commands report empty state there.
- Adds 14 Python tests for the new surface (declarative chaining, end-to-end `from_transport → pipe → sink → run` through real shared-memory channels, and CLI region management against a redirected runtime directory); 85 → 99 tests.
- Extends `verify/check_invariants.py` with cursor-protocol checks: Z3 proves the wrap guard partitions the circle and the send guard (incl. the crash-recovery bias) never writes into an occupied index; CP-SAT proves the cursor gate theorem (crash-free depth never includes an uncommitted slot) and witnesses the crash-leftover zombie state; SCIP verifies the cursor-depth and batch-flush bounds as MIP optima; the dual-handle replay (R4) runs a producer and a consumer over one region through the real implementation.
- Adds Rust unit tests for the cursor protocol: dual-handle round trips, crash-recovery zombie skipping, the biased send guard, WRITING-only ring reads, and rejoin-after-drain.
- Adds `SlotRegionIo` byte-range storage trait with file and memory-mapped backends, `MmapSlotStorage` (memmap2), and name-to-region resolution (`shm_region_path`).
- Generalizes `PersistentShmChannel` over the storage backend with a `create_or_open` constructor for named channels.
- Reports chunk metadata, chunk payload, and maximum message size in channel stats.
- Adds `dsline info` and `dsline bench shm` CLI entry points.
- Adds first cross-process tests (spawn-based producer/consumer round-trips for `ShmChannel` and `FileChannel`, including chunked messages).
- Adds solver-based invariant verification (`verify/check_invariants.py`) with Z3, CP-SAT, and SCIP: sequence-ordering properties, send-plan arithmetic, ring invariants, formal reproduction of the `len`-underflow bug, recovery inference, and replay against the implementation.
- Adds cross-process benchmark harness (`benches/cross_process.py`) vs mp.Queue/mp.Pipe/stdlib shared_memory/ZeroMQ/pynng with throughput, latency, and in-process sections; results in `docs/benchmarks.md`.
- Fixes cross-process races found by the stress tests: Windows file-backed mmap visibility now uses `flush_async_range` (FlushViewOfFile) instead of `flush_range` (FlushFileBuffers disk sync, ~1.2 ms/message); tail inference is now min-seq over committed/pinned slots (correct for gapped rings); a WRITING-only ring behaves as empty; chunked-receive error paths release the pinned slot.
